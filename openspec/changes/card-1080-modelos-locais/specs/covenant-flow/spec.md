## MODIFIED Requirements

### Requirement: Review stance lives in local reviewers not BUGBOT.md
The product SHALL version readonly diff-reviewer and code-reviewer agent files with review constraints but no operational model pin. Spawns SHALL pass the captured client execucao selection explicitly on both Cursor paths and equivalent supported native client paths. Optional REVIEW.md MUST NOT mention Bugbot; BUGBOT.md and native Bugbot MUST NOT be the Code Review gate. Explicit security review MUST NOT replace the pair.

#### Scenario: Pin after operator model edit
- **WHEN** agent files are installed or updated
- **THEN** they preserve readonly constraints without writing or overriding machine selections

### Requirement: Other-client stubs keep inherit without copying the table
All client stubs SHALL point to the canonical runbook and machine selection resolver without copying the role table or operational model values. OpenCode/dsh SHALL no longer instruct inheritance. Grok SHALL require explicit supported native parameters. Bodies SHALL remain at most eight non-empty lines after frontmatter; no client SHALL become a second source of law.

#### Scenario: Stub selection guidance
- **WHEN** a client reads its stub
- **THEN** it resolves its own machine selection or fails visibly, with no picker inheritance

### Requirement: Cursor Task model follows role not picker
The canonical runbook SHALL require explicit native parameters from machine-model-selection for every client's role band. Juizo/execucao roles and isolation, sidecars, Q2-Q6 and review ceiling SHALL remain unchanged. No operational model slug SHALL be a permanent choice in the runbook; forbidden composer-2.5-fast SHALL remain forbidden. Grok reviewers SHALL remain execution. Always-on AGENTS.md SHALL NOT grow with a map. Configuring models SHALL NOT confer authorization or Auto mode.

#### Scenario: Operational change
- **WHEN** the operator changes a supported machine selection
- **THEN** the next role spawn follows it without editing the runbook or requiring another card

### Requirement: Release closeout documents Composer parent chat exception
Release closeout SHALL require the observed parent to match the client's captured local execution selection for that operation. Divergence SHALL cause visible refusal and a new correctly configured session, never retuning the existing parent. This remains the sole exception to silence about the parent picker; arbitrary card chats MUST NOT receive picker recommendations. T16 and release gates SHALL remain unchanged, and one client's model MUST NOT be required on another client.

#### Scenario: Parent no longer matches local execution
- **WHEN** a requested release operation captures a choice different from the current parent
- **THEN** closeout refuses visibly without changing the parent or local selection
